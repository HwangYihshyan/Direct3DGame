【背景のスクロール】

固定表示をやめ、プレイヤーの移動に合わせてスクロールします。

・ワールド幅は 森林 3840 / 平原 4480 / 郊外 5120。
  画面（1280）より広いので、カメラが追従します。
・背景は2層構成です。
  同じ画像を「遠景（視差0.2前後）」と「近景（視差0.55前後）」で

  継ぎ目が目立ちません。

使用している背景は以下のとおりです。

  STAGE 1 森林   Assets\texture\Forest.png
  STAGE 2 平原   Assets\texture\Plain.png
  STAGE 3 郊外   Assets\texture\Surberb.png

高さ720へ拡大して書き出したものです。

ラベルの無い2枚目のパネルを使っています。


【ステータス表示の統合】

「Random OP」を別欄にせず、
基本性能と同じ STATUS 欄へまとめて表示するようにしました。

  ― STATUS ―
  Attack           152   (OP +12.0%)
  Fire Rate        672 RPM   (OP +12.0%)
  Magazine         34   (OP +13.0%)
  Reload           1.74 s   (OP +15.0%)
  Crit Rate        13.0%   (OP +8.0%)

最終値を先に出し、そのうちランダムOPで
上乗せされている分を括弧内に示す形です。
防具も同様に、メインステータスとランダムOPを
1つの欄へまとめています。

0-3. エフェクトと弾の差し替え
==================================================

【追加したファイル】

EffectSystem.cpp / .h   画面エフェクトの生成・更新・描画

設計書 19-5 は種類ごとにファイルを分ける想定ですが、
中身がほぼ同じ処理になるため1つのプールにまとめ、
EffectType で切り替える形にしました。

  EffectType::Muzzle      銃口の閃光      （19-5.3 BulletEffect）
  EffectType::Impact      着弾            （19-5.3 BulletEffect）
  EffectType::Explosion   爆発            （19-5.9 SynergyEffect）
  EffectType::Death       撃破            （19-5.7 EnemyEffect）
  EffectType::Dust        踏み切りの土煙  （19-5.6 PlayerEffect）

設計書 19-5 の共通要件どおり、
一定時間で自動的に消え、同時に96個までに制限しています。
ゲームロジックへは影響しません。


【弾・エフェクトのスプライト】

player.png から抽出しました。

bullets.png   1セル 62x40、4コマ
              0:自機の弾 1:敵の弾 2:マズルフラッシュ 3:散弾
effects.png   1セル 54x53、横4フレーム×縦3種類
              0行目:爆発（オレンジ）
              1行目:着弾（青）
              2行目:撃破（赤）

弾は進行方向へ回転させて描いています。
散弾のときだけ小さいコマへ切り替わります。
敵の弾は、シート上の緑の弾がセル境界とずれていたため、
自機の弾を赤く色替えしたものを使っています。

爆発の炎は EffectSystem が描き、
効果範囲を示す輪だけ GameScene 側で重ねています。

【追加したファイル】

PlayerCharacter.cpp / .h   キャラクター4種の基礎データ
                           （19-2.3 ～ 19-2.6）
PlayerSkill.cpp / .h       固有スキル
                           （19-7.1 ～ 19-7.4）

Player1_Skill ～ Player4_Skill は

【キャラクター】

設計書の相対値を、100 = 1000HP として換算しています。

  Player1  VANGUARD  近距離型
           HP 1200 / DEF 90 / Attack -10% / Speed -10%
           HPと防御が高く前に出て戦える。
           ショットガンやマシンガンと相性が良い。

  Player2  MARKSMAN  遠距離型
           HP 900 / DEF 70 / Attack +20% / Speed +10%
           Crit Rate の基礎値も 5% → 8% と高い。
           スナイパーライフルと相性が良い。

  Player3  BULWARK   防衛型（将来枠・選択不可）
  Player4  REAPER    吸収型（将来枠・選択不可）

Player3 / 4 は設計書 19-2.5 / 19-2.6 の
「将来追加Player枠」なので、
データとスキルだけ用意して選択できないようにしています。
available を true にすれば選べるようになります。


【固有スキル（E キー）】

設計書 19-7.1 の「Synergy Count により性能変化」に沿って、
特定のシナジーが無くても発動はするが、
あるほど強くなる作りにしています。

  Player1  Overdrive Rush
           5秒間 Fire Rate +40% / Move Speed +25%
           Guardian 1個につき最大HPの3%のShield

  Player2  Focus Shot
           4秒間 Crit Rate +40% / HeadShot Damage +60%
           Hunter 1個につき効果時間 +0.5秒（最大+3秒）

  Player3  Aegis Field   最大HP25%のShield（将来枠）
  Player4  Blood Pact    与Damageの8%を吸収（将来枠）

HUD の中央下にスキル名とクールダウンのゲージが出ます。
発動中は黄色く光ります。


【選択方法】

STAGE SELECT 画面で Q / E を押すとキャラクターが切り替わり、
右側に役割・特徴・スキルの説明が出ます。
未実装の枠は自動的に読み飛ばします。


【スプライト】

Player2.png も確認しましたが、絵柄と寸法が別系統だったため、

==================================================
0-5. 今回の調整
==================================================

【メニューの選択演出】

点滅（ちかちか）をやめ、
選択が移った瞬間に光ってから消えていく形にしました。

選択枠の外側へ向かって薄くなる帯を5段重ね、
その明るさを時間で減衰させています。
常時アニメーションしないので目が疲れません。

タイトル・ステージ選択・リザルト・ポーズの
すべてのメニューに適用しています。


【背景スクロールの2分割】

画面を上下に分け、別々の速度で流すようにしました。

  上段（画面の 0%～58%）  空や遠くの山
  下段（画面の 58%～下端）地面に近い部分

手前ほど速く流れるほうが自然に見えるため、
下段を速くしています。

  STAGE 1 森林   上 0.22 ／ 下 0.78
  STAGE 2 平原   上 0.20 ／ 下 0.76
  STAGE 3 郊外   上 0.18 ／ 下 0.74
  BOSS           上 0.16 ／ 下 0.70

下段は 1.25 倍に拡大して描いているので、
手前にせり出して見えます。

上下の速度を逆にしたい場合は、
StageMaps.cpp の各 Build() にある parallax の値を
入れ替えてください。


【ゲーム中の文字】

小さく読みにくかったので、全体的に大きくしました。

  装備の説明など   14pt → 18pt
  武器名・通知     17pt → 22pt
  見出し           22pt → 28pt
  ステージ表示     46pt → 54pt


【ステージの流れ】

区画（1画面ぶん）ごとに進む形へ変えました。

  敵が出現する
    ↓ 全滅させる
  AREA CLEAR と表示される
    ↓ 右端まで歩く
  次の区画へ進み、また敵が出現する

一度進んだ区画へは戻れません。
カメラはプレイヤーではなく「今いる区画」に合わせているので、
後ろへスクロールすることがなくなりました。

区画数は
  STAGE 1 森林   3区画
  STAGE 2 平原   4区画
  STAGE 3 郊外   5区画
  BOSS           2区画（最後の区画にボスが出る）

HUDの右下に「STAGE 1  AREA 2 / 3」と出ます。
制圧すると画面上部に「AREA CLEAR → 右へ進め」が出ます。

敵を全滅させないと右端の手前で止まるので、
敵を無視して走り抜けることはできません。


【ステージ端の表示】

赤い線を消しました。
代わりにプレイヤーが区画の外へ出られないよう
移動範囲そのものを制限しています。

撃ち続ければ壊せます。上に乗ることもできます。

  木箱         耐久 700
  コンクリート 耐久 1100 ～ 2000
  ドラム缶     上記の7割

ボスのHPバーは、ラベルをバーの左横へ移して
数字と重ならないようにしました。
上部のステージ進行バーも位置をずらしています。

通知（AREA CLEAR など）と

==================================================
0-8. 操作とスキルの刷新
==================================================

【マウス操作を廃止】

タイトル・ステージ選択・ポーズを含め、
すべてキーボードだけで操作します。

  W / S ・ ↑ / ↓   項目の選択
  Enter または J     決定
  Esc                戻る

照準もマウスではなくキーボードです。
A / D で向きを変え、↑ / ↓ で45度ずつ傾けます。
狙っている方向は点線と丸印で表示されます。

  ※ シナジーアイコンの説明表示だけは、
     マウスを乗せる方式のまま残してあります。
     操作には関わらない参照用の機能のためです。


【操作一覧】

  A / D          移動
  SPACE          ジャンプ
  SHIFT          ダッシュ
  ↑ / ↓          照準の上下
  J              射撃
  R              リロード
  K              スキル1
  L              スキル2
  Q / 1 / 2      武器の切り替え
  F              装備を拾う／宝箱を開ける
  G              装備を捨てる
  TAB            装備一覧
  Esc            ポーズ


【キャラクターごとのスキル2種】

VANGUARD（Player1）

  K  Shock Wave     CD 9秒
     周囲へ衝撃波。半径260の敵をノックバックさせ、
     最大HPの55%ぶんのDamageを与える。
     Guardian 1個につき半径 +20 / 威力 +5% / 距離 +20。

  L  Bullet Screen  CD 24秒

0-22. 設定画面のクラッシュ修正
==================================================

設定画面へ移った瞬間に落ちる不具合を直しました。
原因は2つあり、どちらも「文字列の範囲外を読む」ものでした。


【原因1】タイトルの文字数指定が実際より多かった

option.cpp の Draw で、見出しをこう書いていました。

    renderTarget->DrawText(
        L"設定",
        6,              ← 文字数
        ...

L"設定" は 2文字です。
6 を渡すと、文字列の終わりを 4文字ぶん越えて読みます。
その先に何があるかは決まっていないため、
文字化けで済むこともあれば、そのまま落ちることもあります。

実際、検査ツールにかけると
ここで global-buffer-overflow が出て停止しました。

wcslen で実際の長さを渡すよう直しています。

    static_cast<UINT32>(wcslen(L"設定"))


【原因2】項目の数と描画回数が合っていなかった

項目名の配列は5個しかないのに、
描画のループが6回まわっていました。

    const wchar_t* names[]
    {
        L"マスター音量",
        L"BGM音量",
        L"SE音量",
        L"フルスクリーン",
        L"戻る"          ← ここまで5個
    };

    for (int i = 0; i < 6; i++)   ← 6回まわる

6回目の names[5] は配列の外なので、
中身の定まらない値をポインタとして使い、
その先を wcslen が読みにいきます。

「操作方法」の項目を戻して6個にそろえ、
さらにループの回数を配列から取るようにしました。

    const int itemCount =
        static_cast<int>(sizeof(names) / sizeof(names[0]));

    for (int i = 0; i < itemCount; i++)

これで、あとから項目を足し引きしても
同じずれが起きません。


【あわせて直したところ】

・「操作方法」を選ぶと ControlsScene へ移るようにしました。
  main.cpp 側には受け口があったのに、
  option.cpp から呼んでいませんでした。

・画面下の操作説明も、実際の長さを渡すようにし、
  内容を日本語へそろえました。

    W / S : 選択    A / D : 変更    Enter : 決定    Esc : 戻る


【確認したこと】

設定画面だけを動かす検査を作り、
上下キーで全6項目を選びながら40フレーム描画しました。

  修正前  global-buffer-overflow で停止
  修正後  最後まで落ちずに完走

あわせて、他に同じ書き方が残っていないか
すべての .cpp を調べましたが、
文字数を直接書いている箇所は残っていませんでした。

0-25. 敵の射撃と操作方法画面の背景
==================================================

【敵が弾を撃つようになりました】

これまで撃ってきたのは遠距離型とボスだけでしたが、
すべての敵が撃つようになりました。

強さに応じて、撃つ間隔と狙いの正確さを変えています。

  敵        HP    間隔   射程  弾速  Damage比  狙いのぶれ
  Runner    560   5.4秒  420   380   0.26      大きい
  Grunt     900   3.8秒  540   400   0.34      やや大きい
  Shooter   720   2.0秒  620   480   0.52      小さい
  Brute    2300   3.6秒  500   330   0.58      やや大きい
  Elite    3400   2.0秒  640   500   0.48      小さい

Damage比は接触Damageに対する割合です。
弱い敵は「たまに撃ってくる牽制」、
Shooter と Elite は「きちんと狙ってくる」という差になります。

ボスは以前からの専用の攻撃をそのまま使います。


【当たらないための逃げ道を用意しています】

一方的に削られないよう、次の条件を入れています。

  ・距離130より近い敵は撃たない（殴りにくる）
  ・画面に映っていない敵は撃たない
  ・敵の弾は画面内に7発まで
  ・敵ごとに最初の待ち時間をずらし、一斉射撃にしない
  ・弾は障害物で止まるので、物陰に入れば防げる

距離を取り続けるのは Shooter とボスだけです。
他の敵は今までどおり近づいてきます。


【難易度の調整】

弾のDamageには、ステージ倍率をそのまま掛けていません。

    bulletScale = 1.0 + (ステージ倍率 - 1.0) * 0.5

接触Damageと同じだけ強くすると、
後半のステージが弾だけで押し切られてしまうためです。

自動で動かす検証を何度か回して数字を見ています。

0-26. 今回の修正
==================================================

【プレイヤーが画面の外へ出ないようにする】

区画の境目で、プレイヤーが画面の左外へ抜けることがありました。

カメラは「今いる区画」に固定しているのに対し、
プレイヤーの移動できる範囲は区画そのもので決めていました。
そのため、区画を移った直後などに
「区画の中だが、カメラの写していないところ」
という位置が作れてしまっていました。

区画で挟んだあと、カメラの写している範囲でもう一度挟みます。

    const float viewLeft  = m_camera.GetX() + 6.0f;
    const float viewRight = m_camera.GetX() + 1280 - 幅 - 6.0f;

    m_playerX = std::clamp(m_playerX, viewLeft, viewRight);

カメラが次の区画へ動くと、左の壁も一緒に動くので、
プレイヤーは押し出される形で自然に次の区画へ入ります。

上方向も同じ理由で抜けることがあったため、
画面の上端でも止まるようにしました。
高い段差から跳んだときや、Blink で浮いたときに効きます。

自動で動かして確認した範囲です。

    画面内 X  137 ～ 1274 （画面は 0 ～ 1280）
    最上 Y    399         （画面の上端は 0）


【制圧したら進む先に線を引く】

区画の敵を全滅させると、
その区画の右端に線が出るようになりました。

  ・光の帯を5段重ねて、ゆっくり明滅させる
  ・上へ流れる矢印を6つ
  ・地面に足元の印
  ・線の下に行き先を出す

色と文字は、その先に何があるかで変わります。

  途中の区画    緑　「NEXT AREA」
  最後の区画    金　「STAGE GOAL」

敵を倒したあと、どこまで歩けばよいのかが
画面を見ただけで分かります。

線が出るのは制圧したあとだけです。
戦っている間は出ないので、視界の邪魔になりません。

7. 設計書から意図的に変更した点
==================================================

【1】銃の基礎攻撃力

設計書15章の例に「Bolt Action Rifle 基礎ATK 180」とありますが、
連射55RPMでは DPS 165 となり、Assault Rifle（DPS 1000）の
6分の1になってしまいます。
例示用の数値と判断し、実際の戦闘が成立するよう調整しました。

    Assault Rifle       100  （設計書どおり）
    Heavy Machine Gun    70  （設計書どおり）
    Bolt Action Rifle  1000  （DPS 917 ＋ HeadShot倍率 ×3.0）

DPSがおおよそ揃うよう baseAttack と roundsPerMinute を設定し、
「威力★が高い＝1発が重い代わりに連射が遅い」という関係を
作っています。設計書の★評価は powerRating などにそのまま
残してあるので、数値の再調整は EquipmentDatabase.cpp だけで
行えます。


【2】Redeye 6

設計書では「HeadShotは必ずCritになる／HeadShot Crit Damage +20%」
ですが、HeadShot Damage の加算値は 4 と同じ +30% に据え置き、
必中Crit のぶんで強くなる形にしています。
加算と必中Critが重なると精密射撃ビルドが突出しすぎるためです。


【3】防具のメインステータス

設計書5章の「防具はその部位のメインステータスに倍率を掛ける」
に対応するため、部位ごとに以下を定義しました。
設計書に具体的な数値の記載が無かった部分です。

    HEAD   Crit Rate     +5.0%
    BODY   Max HP       +220
    LEG    Reserve Ammo  +30%
    ARM    Attack        +6.0%
    BOOTS  Move Speed    +5.0%

ここにだけレアリティ倍率が掛かります。
Fire Rate や Crit へ一括で倍率を掛けない、という
設計書17章のルール5を守っています。

11. サウンド（設計書 19-2.12）
==================================================

【仕組み】

AudioManager.h / .cpp を追加しました。

    mp3  →  Media Foundation で PCM へ展開  →  XAudio2 で再生

Windows に最初から入っている機能だけを使っているので、
追加のライブラリや DLL は要りません。
リンクするライブラリは AudioManager.cpp の中で
#pragma comment 指定しているため、
プロジェクトの設定を触る必要もありません。

音声ファイルが1つも無くても、無音のまま普通に起動します
（19-13 共通エラー処理と同じ考え方）。
読み込みに失敗したファイルは「失敗した」と覚えておき、
毎フレーム読み直さないようにしています。


【BGM】

Assets\sound へ次の名前で置くと、その場面で流れます。
どれもループ再生です。

    bgm_title.mp3      タイトル / ステージ選択 / オプション /
                       操作説明 / ランキング
    bgm_stage1.mp3     STAGE 1 森林
    bgm_stage2.mp3     STAGE 2 平原
    bgm_stage3.mp3     STAGE 3 郊外
    bgm_boss.mp3       FINAL BOSS
    bgm_result.mp3     リザルト
    bgm_gameover.mp3   ゲームオーバー
    bgm_gameclear.mp3  ゲームクリア

ステージ用の BGM は背景テクスチャと同じ扱いで、
MapBase が m_bgmPath として持っています。
実際の割り当ては StageMaps.cpp の各 Build() にあります。

    Map1::Build()     m_bgmPath = BgmPath::Stage1;
    Map2::Build()     m_bgmPath = BgmPath::Stage2;
    Map3::Build()     m_bgmPath = BgmPath::Stage3;
    MapBoss::Build()  m_bgmPath = BgmPath::Boss;

ファイル名を変えたい場合は AudioManager.h の
BgmPath を書き換えてください。

同じ曲へ切り替えようとした場合は鳴らし直しません。
リトライのたびに曲が頭へ戻ることはありません。


【SE】

Assets\sound に置いてあるファイルを、次の場面で鳴らします。

    se_shot.mp3           射撃（散弾でも1回だけ）
    se_headshot.mp3       頭に当てたとき
    se_dash.mp3           Shift でダッシュしたとき
    se_enemy_hit.mp3      敵の接触ダメージを受けたとき
    se_skill_assault.mp3  突撃兵で K スキルを使ったとき
    se_skill_heavy.mp3    重装兵で K スキルを使ったとき
    se_menu_decide.mp3    メニューで決定したとき
    se_menu_back.mp3      メニューで戻ったとき / ESC
    se_scene_change.mp3   画面が切り替わったとき

ファイル名は必ず半角英数にしてください。
日本語名にすると、zip でやり取りした際に文字化けし、
その場で開けなくなって無音になります。

対応表は AudioManager.cpp の SE_PATH にあります。
SeId の並びと同じ順に書いてください。

同じ音が重なっても切れないよう、1音につき4本の
再生枠を用意しています。


【音量】

オプション画面の Master / BGM / SE を動かすと、
その場で音へ反映されます。
Master と SE は動かした瞬間に1度鳴らすので、
今の大きさが耳で確かめられます。

タイトルへ戻ったときに config.txt へ保存され、
次の起動時に読み込まれます。


【注意】

AudioManager.cpp は UTF-8（BOM 付き）で保存してあります。
編集するときは文字コードを変えないでください。

EffectSystem.cpp の DrawImpactBurst() が中身です。

    中心の閃光    すぼみながら消える
    リング        広がりながら薄くなる
    火花          弾の来た向きへ扇状に跳ね返る（7本）

    SPARK_COUNT  火花の本数
    spread       火花の広がる角度（現在 ±60度）
    lengthScale  火花の長さのばらつき

継続時間は GetDuration() の EffectType::Impact（現在 0.26秒）、

13. レベルデザインの作り直し
==================================================

【何を変えたか】

terrain_*.png は 96角・横12列×縦9行のタイルシートですが、
これまでは先頭の5マスしか使っていませんでした。

    0列目 天板 / 1列目 中詰め / 2～4列目 障害物

木・柵・建物といった飾りは画像を使わず、
GameScene.cpp の中で図形として描いていました。

今回、シート全体を使えるようにして、
飾りも地面もすべてタイルから描くようにしています。


【データの持ち方（MapBase.h）】

TileRef を追加しました。col / row でマスを指定します。
負の値なら「画像を使わない」という意味です。

    MapProp::tile         飾りに使うマス
    MapProp::flip         左右反転して置く
    MapProp::foreground   プレイヤーより手前に描く
    MapObstacle::tile     障害物に使うマス
    MapBase::m_platformTopTile   足場の天板
    MapBase::m_platformFillTile  足場の中詰め

宝箱にも高さを持たせました（MapChestPoint::baseY）。
0以下なら地面、それ以外はその高さへ置きます。
足場の上に置けるので、登る理由を作れます。


【描画（GameScene.cpp）】

・DrawProps(bool foreground)
  奥の飾りと手前の飾りを2回に分けて描きます。
  手前の下草がプレイヤーの足元へかかり、奥行きが出ます。

・DrawGround()
  地面もタイルで敷き詰めるようにしました。
  以前は無地の緑一色だったため、
  タイルで描いた段差から浮いて見えていました。
  ワールド座標に合わせて並べるので、歩くと地面も流れます。

・等倍で並べる地面と段差は NEAREST_NEIGHBOR で描きます。
  LINEAR だと隣のマスの色を拾い、
  マスの境目に細い線が出るためです。

いずれも画像が読めなかった場合は
従来どおり図形で代用します（設計書 19-13）。


【段差の決まりごと】

AddPlatform(段数) が高さを計算するので、
96の倍数以外の段差は作れないようにしてあります。

ジャンプで登れる高さは

    JUMP_POWER^2 / (2 * GRAVITY) = 700^2 / (2 * 1900) ≒ 129

なので、1段（96）は登れますが2段（192）は登れません。
高い足場には必ず1段の踏み台を隣へ置いてあります。


【各ステージの狙い】

  STAGE 2 平原

  STAGE 3 郊外
    高低差が一番大きく、石段と屋上を渡っていきます。
    足場は草の乗った石垣（8,0）と石積み（3,6）で、
    村の石段に見えるようにしました。
    民家・井戸・鐘のアーチ・街灯・市場・鉄柵。

  FINAL BOSS

15. HP回復ドロップ／ヘッドショット／スキルの変更

【HP回復アイテム】

敵を倒すと一定確率で救急箱を落とすようにしました。
弾薬と同じく、近づくと吸い寄せられ、触れるだけで拾えます。

  出現率    通常の敵 12% ／ Elite・Boss 40%
            さらに HPが減っているほど上がる（最大 +18%）
            HPが満タンのときは落とさない
  回復量    最大HPの18%

  絵        Assets\texture\health_pickup.png（64角・新規）
            items.png と同じ、太い輪郭のドット絵に合わせています。
            弾薬は黄色、回復は赤い光を敷いて見分けられるように
            しています。

  実装      GameScene の HealthPickup / SpawnHealthPickup /
            DrawHealthPickups。AmmoPickup と同じ作りです。

出現率は GameScene.cpp の「HP回復ドロップ」の箇所、
回復量は同じ場所の 0.18f で変えられます。


【ヘッドショットの重複】

ショットガンは1回の射撃で何発も同時に飛ぶため、
全弾が頭に当たるとヘッドショットが数回ぶん重なっていました。
表示も撃破数も跳ね上がってしまう状態です。

弾に「何回目の射撃で出たか」（Bullet::shotId）を持たせ、
同じ射撃のぶんは最初の1発だけをヘッドショットとして扱います。
2発目以降は通常命中になり、倍率も乗りません。

別の射撃であれば、同じフレームでもきちんと数えます。


【飾りが浮いていた件】

terrain_*.png の飾りのマスは、絵の下側に透明な余白がある
ものが多く（郊外の (11,4) 木のベンチは96のうち32が余白）、
マスの下端を地面に合わせると絵が浮いて見えていました。

マスごとに「絵の下端」を数えた表を作り、
その余白ぶんだけ下げて描くようにしています。

    TerrainTileBottom.h / .cpp   表（自動生成）
    tools/make_tile_bottom.py    画像から数え直すスクリプト

テクスチャを差し替えたら make_tile_bottom.py を実行してください。

障害物は当たり判定があるため、下げると絵と判定がずれます。
そこで、絵が地面まで届いていないマスを使っていた箇所は
届くマスへ差し替えました。

    平原  干し草かご (7,6) → 木箱 (2,0)
    郊外  麻袋 (4,0)       → 樽 (3,7)
    郊外  干し草 (8,7)     → 石ブロック (8,8)
    ボス  麻袋 (4,0)       → 石ブロック (8,8)


【突撃兵の K スキル】

「足止めの一撃」を「制圧射撃」へ変更しました。

  発動から10秒間
      攻撃力    +30%
      連射速度  +45%
      弾薬を消費しない

  上昇量は発動した瞬間の 強襲(Assault) の数だけ伸びます。
      攻撃力    強襲1個につき +2%
      連射速度  強襲1個につき +3%

  クールダウン  26秒（効果時間が長いので伸ばしています）

リロードも弾切れも気にせず撃ち続けられるスキルなので、
攻めきることが強さになる突撃兵に合わせた形です。

  実装  PlayerSkill の Marksman_SuppressiveFire
        SkillBuff::infiniteAmmo を GameScene の
        「弾薬の消費」判定が見ています。

上昇量は PlayerSkill.h の ATTACK_BONUS /
FIRE_RATE_BONUS で変えられます。
説明文は PlayerCharacter.cpp にあるので、
数値を変えたら合わせて直してください。

なお、これまで使っていた SkillBuff::slowOnHit は
使う側がいなくなったので削除しました。
Enemy の slowFactor / slowTimer は残してあります。

装備一覧の「◆ 新着」を「◆ NEW」に戻しました。

18. SE / BGM の追加と鳴らし方の整理
==================================================

【1回だけ鳴らす曲を分けた】

結果画面のファンファーレは短いので、
ループさせるとしつこく鳴り続けていました。

AudioManager に PlayJingle() を足し、
ループするBGMと1回だけの曲を分けています。

    PlayBgm      ループする。同じ曲なら鳴らし直さない
    PlayJingle   1回だけ鳴って止まる。呼ぶたび頭から

    ループ    bgm_title / bgm_stage1～3 / bgm_boss
    1回だけ   bgm_stageclear / bgm_result
              bgm_gameover / bgm_gameclear

【ゴールラインを越えたとき】

ゴールラインを越えると、ステージのBGMを止めて
bgm_stageclear.mp3 を1回だけ鳴らします。

    GameScene::UpdateArea()      鳴らし始める
    GameScene::UpdateStageFlow() 鳴り終わるまで待ってから移る

リザルトへ移るのは、次の2つがどちらも済んでからです。

    ・クリア演出の3秒（m_stateTimer）
    ・ファンファーレを最後まで鳴らし切る

鳴り終わったかどうかは Audio::IsJinglePlaying() で見ています。
XAudio2 に積んだバッファが尽きたかを調べているだけなので、
曲の長さを別に持つ必要はありません。

曲が置かれていない場合は IsJinglePlaying がすぐ false を返す
ので、演出の3秒だけで先へ進みます。
長すぎる曲を入れられても止まらないよう、
20秒で打ち切る上限も入れてあります
（GameScene.cpp の STAGE_CLEAR_WAIT_MAX）。

今の bgm_stageclear.mp3 は約8.5秒なので、
ゴールしてからリザルトまで8.5秒ほど待つことになります。
長く感じる場合は曲を短くするか、上限を下げてください。

==================================================
19. シェーダ（.cso）の追加
==================================================

【なぜ入れたか】

これまで描画は Direct2D だけで完結しており、
HLSL を1行も書いていませんでした。
そのため .cso（コンパイル済みシェーダ）も存在しませんでした。

DirectX 11 は使っていましたが、役割は
「スワップチェーンとバックバッファを用意する」だけで、
Draw / DrawIndexed も呼んでいませんでした。

そこへ、画面全体へ掛ける後処理を1枚はさみました。


【流れ】

    Direct2D  →  オフスクリーンのテクスチャ
                     ↓  ScreenVS.cso / ScreenPS.cso
                 バックバッファ

ゲームの描画コードは一切変わっていません。
Direct2D の描き先がバックバッファから
オフスクリーンへ変わっただけです。


【ファイル】

    Shaders\ScreenVS.hlsl    画面を覆う三角形を作る
    Shaders\ScreenPS.hlsl    ビネットと被弾時の赤み
    PostEffect.h / .cpp      オフスクリーンとシェーダの管理

.hlsl はビルド時に fxc がコンパイルし、

    $(OutDir)Shaders\ScreenVS.cso
    $(OutDir)Shaders\ScreenPS.cso

へ出力されます。実行時は PostEffect が
"Shaders\ScreenVS.cso" を読んでシェーダを作ります。

つまり .cso は実行に必要です。
exe と一緒に Shaders フォルダも配ってください。


【頂点バッファを使っていない】

ScreenVS.hlsl は SV_VertexID（0/1/2）から座標を組み立てます。
そのため頂点バッファも入力レイアウトも作っていません。
Draw(3, 0) を呼ぶだけで画面全体が覆えます。

四角形（三角形2枚）ではなく、画面より大きい三角形1枚に
しているのは、2枚の継ぎ目に線が出るのを避けるためです。


【効果】

    ビネット      画面の四隅を落とす。中央へ目が向く。
    被弾時の赤み  縁だけ赤くする。中央は残すので敵は見える。

被弾の強さは GameScene::GetDamageFlash() から
定数バッファ（ScreenParams）で渡しています。

見た目を変えたいときは ScreenPS.hlsl を直してください。
再ビルドすれば .cso も作り直されます。


【用意できなかったときの動き】

次のどれかで失敗した場合、後処理をあきらめて
これまでどおりバックバッファへ直接描きます。

    ・オフスクリーンのテクスチャが作れない
    ・.cso が見つからない、または壊れている
    ・Direct2D がオフスクリーンへ結び付けられない

絵は素のままになりますが、ゲームは問題なく動きます
（設計書 19-13 共通エラー処理と同じ考え方）。
